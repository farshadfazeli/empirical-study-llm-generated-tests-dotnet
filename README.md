# LLM-Generated Tests for C# Libraries: Coverage vs. Mutation Score

A small, reproducible empirical study of whether unit tests generated by a large language model (LLM) for C# code reach high code coverage but a much lower mutation score.

This is **not** a claim of novelty. A coverage-versus-mutation gap for LLM-generated tests has been reported before; this study checks whether the same pattern appears in a few small .NET libraries, using Coverlet and Stryker.NET.

## Research questions

- **RQ1.** How do coverage and mutation score of LLM-generated tests compare with those of each library's existing human-written tests?
- **RQ2.** Does one feedback round (showing the model the mutants that survived the first round) improve the mutation score compared with a basic prompt?
- **RQ3.** What kinds of mutants survive the LLM-generated tests? (manual classification of a sample)

## Method

**Subjects.** Eight small, pure-logic open-source C# libraries (.NET 8 compatible, no database, network, or UI), each cloned at a pinned commit. For each library, 3 to 5 source files are chosen and recorded in `libs.csv`; mutation testing is restricted to those files.

**Model.** One LLM, configured through environment variables (`LLM_MODEL`, `LLM_BASE_URL`, `LLM_API_KEY`), temperature 0.2.

**Prompt strategies.**
- **A (basic):** the model receives the class source and signatures of its dependencies and is asked to write xUnit tests.
- **B (feedback):** the same as A, followed by a second round in which the surviving mutants from round 1 are shown and the model is asked for additional tests.

Each (class, strategy) pair is generated 3 times to measure variance. All prompts and raw model outputs are stored.

**Validation.** Generated tests are compiled and run. Compile errors, failing tests, and timeouts are recorded as results. Tests that fail on the original code are removed, and the number removed is reported.

**Measurement.** Line and branch coverage with Coverlet; mutation score with Stryker.NET, for the human tests and for each generated suite.

**Surviving mutants.** A stratified sample of 60 surviving mutants is exported and labeled manually (RQ3).

## Reproduce

Each pipeline step is a separate command:

```powershell
python src/select_libs.py
dotnet tool restore
python src/generate.py --library Ardalis.GuardClauses --strategy basic --repeat 1 --class-file src/GuardClauses/Guard.cs
python src/create_test_project.py --library Ardalis.GuardClauses --strategy basic --repeat 1
python src/validate.py --library Ardalis.GuardClauses
python src/coverage.py --library Ardalis.GuardClauses --suite human --project data/raw/pilot/Ardalis.GuardClauses.HumanTests/Ardalis.GuardClauses.HumanTests.csproj
python src/coverage.py --library Ardalis.GuardClauses --suite basic_repeat_1_generated --project data/raw/llm/Ardalis.GuardClauses/basic/repeat_1/generated-tests/GeneratedTests.csproj
python src/measure.py --library Ardalis.GuardClauses --suite human
python src/feedback_round.py --library Ardalis.GuardClauses
python src/analyze.py
python src/survivors.py
```

Model configuration:

```powershell
$env:LLM_API_KEY = "..."
$env:LLM_MODEL = "..."
$env:LLM_BASE_URL = "https://api.openai.com/v1"
```

The API key is read only from the environment and is never stored in files, prompts, CSVs, or git.

## Pilot coverage result

Coverlet was run on the human baseline and produced a Cobertura report under
`data/raw/reports/`. The observed aggregate coverage is line coverage `0.0203`
(`12/591` lines) and branch coverage `0.0365` (`9/246` branches). The generated
Qwen suite did not compile, so its coverage run is recorded as `failed` with no
coverage values; it is not silently omitted. The analysis-ready rows are in
`data/results/coverage.csv`.

Stryker.NET 4.8.0 was then run against the pilot target file. It created 352
mutants; 5 were killed, 3 survived, 47 had no coverage, 2 caused compile
errors, and 295 were ignored by Stryker's filters. Stryker reported a mutation
score of `0.0909`. The complete JSON report is retained under
`data/raw/reports/Ardalis.GuardClauses/human/reports/`, with the analysis row
in `data/results/mutation.csv`. These are pilot observations, not conclusions
about the full study.

## Pilot validation result

The revised Qwen prompt was run for the three requested basic repetitions; an
additional repaired-prompt output was retained separately. NuGet restore
succeeded for all four suites when the official NuGet source was selected, but
none compiled. Therefore the observed pilot compile rate is `0/4 = 0.0` and
the pass rate is `0/4 = 0.0`. The rows and compiler diagnostics are retained in
`data/results/validation.csv`, and the latest aggregate is in
`data/results/validation_summary.csv`. The failures remain part of the result;
they are not converted into missing data.

## Compact-context prompt check

`src/generate.py` now supports `--compact-context`, which sends declarations,
public signatures, and a usage example instead of the full implementation
body. The Qwen prompt fell from about 2,700 tokens to 558 tokens. The resulting
`compact_context_2` output had valid brace structure and restored successfully,
but still failed compilation because generated assertions and identifiers were
invalid. Its result is recorded separately in `data/results/validation.csv`; it
is not counted as a passing LLM suite.

As a diagnostic prompt check, a minimal fixed test template was sent to Qwen
with `--minimal-template`. That output restored, compiled, and passed its
original-code test: `compile_rate = 1.0` and `pass_rate = 1.0` for this single
run. It is not counted as the basic strategy result because the prompt supplied
the complete test shape; it only confirms that the generated-test project and
validation path work when the model returns valid C#.

## Threats to validity

- **Training-data contamination:** the libraries are public and may appear in the model's training data.
- **Single model:** results may not generalize to other models.
- **Small sample:** only eight libraries and a limited number of classes.
- **Mutation operators:** limited to those implemented in Stryker.NET; equivalent mutants are not filtered out.
- **Manual labeling:** surviving mutants are labeled by one person.
- Build errors and timeouts are reported, not silently dropped.
